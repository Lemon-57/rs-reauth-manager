# 账号重新授权 v0.1.17

修复退回 Free 时的授权确认、2FA 分类恢复及页面操作与错误展示。

## 兼容要求

- 宿主范围保持 RS `>=3.29.1, <3.30.0`。
- 继续使用 v3.29.1 对应公开 SDK，固定提交 `743a3aba70a4f78f27fb53d80a6e719599d2fe5e`，使用匹配合同源码的 CLI 在本机重新编译和打包。
- 安装包为 RPC v4、management v2、maintenance v1、manifestVersion 2，不是只修改版本字段。
- 保持插件 ID、配置和状态命名空间；不改变任务队列的串行执行模式，不包含并行执行功能。

## Free 工作区恢复

- 修复手动退回 Free 在授权确认页面没有提交工作区选择、最终出现 HTTP 200 却无有效回调的问题。
- 仅选择可安全判定的唯一候选；不默认选择第一个 Team 或未知工作区。没有候选或存在歧义时显示对应具体原因。
- 返回令牌必须匹配同一邮箱、用户及选中的工作区，并确认为 Free，否则不写回；原工作区仍可用时，普通授权继续保留原工作区，不自动从 Free 切换到新加入的 Team。
- 成功恢复后写回原账号并停止调度，仍保留代理、分组、备注和其他受保护配置。

## 按错误类型恢复登录

- 明确的动态码无效、过期：同一挑战最多提交三次不同动态码。
- 登录身份、密码或 MFA 步骤明确返回 HTTP 400/409 的 `invalid_state`：放弃旧 Cookie 和挑战，使用原账号代理重建一次登录会话；再次失败即结束，不无限重登。
- 普通授权保持 RS 待完成流程的 state 和 PKCE；Free 恢复在新会话中生成独立 PKCE，不混用授权码和 verifier。
- 同一任务内不重复使用已提交的动态码；新码等待按 30 秒周期另加 5 秒余量，修复刷新边界的误超时和最小轮询间隔越过截止时间的问题。
- 429、封禁、付款、密码错误、人工验证、无明确机器码的 409、传输异常、回调校验失败和令牌交换失败，不自动猜测换码或重登。
- 重建后仍失败时，保留首次及本次的具体阶段、原因和可用 HTTP 状态；新的工作区错误不会被恢复历史覆盖。
- 单号 420 秒总时限不延长，不自动重新排队，不重放凭据写回。

## 页面与操作

- 普通单号与批量重新授权点击后直接提交，移除普通授权确认弹窗。
- 提交时按最新目录检查适用账号并去重，保留双击防重及提交响应丢失后的只读核对，不自动重复发送。
- 强制替换其他工作区仍须明确选择并确认，不受普通授权和退回 Free 的直接提交交互影响。
- 错误正文完整换行、行高自然展开，不再受单行省略样式裁剪；长机器码也不会撑宽或覆盖下一行。
- 保留历史成功重新进入时显示未执行、本次批次统计、完整邮箱、分组、会员筛选和分页行为。

## 验证范围

- 本机通过 106 项 Python 离线测试、14 项 Rust 测试、44 项真实 SDK 子进程 RPC 场景、15 项前端桥测试、21 项任务交互测试及 203 项源码约定检查。
- Rustfmt、Clippy、前端类型检查与生产构建通过；Linux x86_64 交叉编译及匹配 CLI 打包后核对协议、资源摘要与内嵌协议源码。
- 使用模拟数据验证长错误在桌面、窄桌面和手机上完整展示；浏览器验证普通单号直接提交且强制工作区确认保留。
- 后续批量和手机直接提交的浏览器验收遇到自动化工具超时，未计为通过；对应提交、防重、去重及响应丢失行为已由离线逻辑测试覆盖。
- 本版未进行真实账号完整授权或生产安装；本机未实际执行 Linux 二进制，交叉编译、模拟及制品校验不等同于生产验收。
- 不包含 2FA 解绑、重新绑定、新密钥写回或周限插件更新。
