# 账号重新授权 v0.1.18

修复授权页面后备解析，并按明确规则自动切换个人 Free 与唯一 Team 工作区。

## 工作区与调度

- 原 Team 工作区已失效、只剩唯一可确认的个人 Free：自动切回同一用户的 Free，写回原账号并停止调度。
- 原记录为 Free、后来加入唯一明确的 Team/Business：自动切换到该团队工作区，验证写回成功后开启调度，原本停用的 Free 账号也会开启。
- 有多个团队候选、身份不一致、类型不明确或证据冲突时，不默认取首项；多个候选需手动选择目标。
- Cookie 与当前授权页的工作区证据合并后判断唯一性，避免旧 Cookie 中的单一 Team 覆盖当前页的多个 Team；没有 Team 时仍可保留原个人工作区。
- 使用独立 state 和 PKCE 验证切换目标，不混用宿主待完成流程的 verifier；核对同一邮箱、用户、工作区、主体、套餐、凭据版本和账号空闲状态。
- 自动切换只在空闲时暂停该账号调度并写回，Team 凭据完整读回且配置与版本未变后才开启调度，并回读最终状态。写回或开启结果不确定时要求人工核对，不自动重放。
- 保留原名称、备注、分组、代理、权重、并发和模型权限，不新建账号；不批量重登、不自动恢复历史失败任务。

## 协议适配修复

- 会话查询返回 403 或超时后，继续解析授权页面及下一步地址，不提前误判没有 Free 空间。
- 解析有界 JSON、脚本 hydration 与引用式工作区对象，保留全部候选及类型，精确匹配 ID；不执行页面脚本、不以字符串包含判断工作区。
- 畸形、重复、冲突及超量数据不自动选择；候选缓存不再把已拒绝的列表截断后重新放回。
- 修复被拒绝的工作区选择仍被视作成功绑定，以及异常 Cookie 数据使后备解析崩溃的问题。
- 会话查询错误使用独立阶段；候选判断不再沿用无关的 403 或超时，后续错误不被旧错误覆盖。
- 令牌交换禁止自动跟随重定向，避免将授权码和 PKCE verifier 转发到其他地址。
- 五个提取的上游协议模块保持原样，修复位于插件适配层。

## 兼容与已知边界

- 继续适配 RS `>=3.29.1, <3.30.0`，RPC v4、management v2、maintenance v1、manifestVersion 2；固定 SDK 提交 `743a3aba70a4f78f27fb53d80a6e719599d2fe5e`，本机重新编译并用匹配 CLI 打包。
- 不包含并行执行、2FA 解绑或密钥轮换，不改变周限插件。
- 原工作区普通授权仍经 RS 原生完成路径。源码审查发现该路径的写回前新旧身份比较不足，本次未修改宿主；不能宣称已解决该独立边界。自动工作区切换走独立 PKCE 与主体校验，不使用该普通写回分支。详见仓库 `docs/UPSTREAM-PARITY.md`。

## 验证

- 本机通过 152 项 Python 离线测试、15 项 Rust 测试、54 项真实 SDK 子进程 RPC 场景、15 项前端桥测试、21 项任务交互测试和源码约定检查。
- 同一模拟响应下，原项目与修复后插件均能在会话 dump 403 后继续选择工作区并完成模拟 Free 令牌交换；额外验证两种自动切换、原停用账号开启、多个 Team、不匹配身份、配置变化和开启结果不确定。
- Rustfmt、Clippy、前端类型检查与生产构建、本机 Linux x86_64 交叉编译及安装包摘要、资源和内嵌源码一致性检查通过。
- 测试全部使用虚构账号或模拟传输，不表示真实账号完整授权已验收；上线仅通过隔离自检与原生插件切换，不以自动重登真实账号作为验收手段。
