# 账号重新授权 v0.1.16

集中发布错误诊断、直接退回 Free、历史结果展示及 RPC v4 兼容更新。

## 兼容要求

- 宿主范围为 RS `>=3.29.1, <3.30.0`，不适用于旧版宿主。
- 使用 v3.29.1 对应公开 SDK，固定提交 `743a3aba70a4f78f27fb53d80a6e719599d2fe5e`；从相同 SDK/CLI 合同源码本机构建打包工具，重新编译和打包，不是仅修改版本字段。
- 安装包为 RPC v4、management v2、maintenance v1，manifestVersion 仍为 2。
- 保持插件 ID、实例配置和私有状态命名空间，已有任务不会因安装新版本而自动重登或重放。

## 错误诊断

- 跟踪 request、get、post 三种上游调用路径，保留打开登录页、获取安全校验令牌、密码验证、2FA、选择工作区、授权跳转及令牌交换的具体阶段。
- 将本地动态码生成失败与上游验证失败分开。先收到验证拒绝、再等待新码超时，会保留两次独立原因，不把此前 HTTP 状态放到本地取码错误上。
- 明确区分动态码无效、过期、验证挑战状态无效、限流及无明确原因的 HTTP 409 冲突；已知上游机器码按白名单展示，不仅凭 409 判断密钥错误。
- 区分非 JSON 响应、JSON 结构异常、协议内部异常及请求超时、DNS、TLS、连接失败，不再把内部解析异常统一报成代理错误。
- 上游明确返回封禁或停用状态码时显示对应账号错误；Payment Required 单独提示，不把普通 402/403 直接判定为封禁。
- 不展示上游响应正文、密码、动态码、2FA 密钥、RT 或完整认证代理。历史任务没有保存的信息无法还原，不凭空补写原因。

## 页面与操作

- “退回 Free”点击后直接提交，不再弹出确认窗口或要求勾选；仍验证同一邮箱、用户、Free 套餐、凭据版本及账号空闲状态，成功写回原账号后停止调度。
- 防止重复点击创建重复任务；提交响应丢失时只读回任务，不自动重发登录或写回请求。
- 重新进入页面后，历史成功显示“未执行”，最近一次历史失败、需核对或中断保留安全错误原因；本次刚执行的结果正常显示。
- 成功与未完成计数继续仅统计本页最近一次提交，重新进入归零，后台历史不删除。
- “强制写回其他工作区”仍需要明确选择工作区并确认，不受直接退回 Free 的交互调整影响。
- 支持 Free 在内的全部套餐 OAuth 账号，账号分组、代理、备注、名称及其他原配置保护保持不变；不改变独立周限插件的账号范围。

## 验证范围

- 本机通过 11 项 Rust 测试、44 项真实 SDK 子进程 RPC v4 协议场景、74 项 Python 离线测试、15 项前端桥测试、20 项 Vue 任务交互场景及 218 项源码约定检查。
- Rustfmt、Clippy、前端类型检查与生产构建通过，完成 Linux x86_64 本机交叉编译、匹配 CLI 打包及资源、协议版本、摘要和内嵌源码校验。
- 打包器 10 项功能测试通过；两项上游帮助文案测试在 Windows 因 `cpr-plugin.exe` 与无后缀命令名断言不同而失败，不计为通过，未修改上游测试掩盖差异。
- 已用本地模拟数据验证桌面、手机的直接退回 Free，无确认弹窗、仅一次提交及成功后的 Free/停用状态显示。
- **仍为实验性功能。** 本版未进行真实账号完整授权、生产安装或重置卡消费，未在本机实际执行 Linux 二进制；模拟宿主、交叉编译及制品验证不等同于完整生产验收。
- 不包含 2FA 解绑、重新绑定或新密钥写回功能。
