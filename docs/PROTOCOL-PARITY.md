## v0.1.28 修正

- 初始客户端从 `chrome124,chrome133a,chrome136,chrome120` 中随机选择，交由原版 ChatGPTClient 生成实际浏览器配置和请求头。

`vendor/lib` 下的登录、OAuth、HTTP、安全校验和工具代码按上游原样保留。共享干净会话、Cookie、设备 ID、请求头、显式代理和禁用环境代理均由相同实现提供。插件将 OAuthClient 会话替换为 ChatGPTClient 的同一会话，与原版一致；关闭被替换的空闲会话只释放资源，不发送网络请求。

## RS 必须保留的职责与保护

原版自行生成 PKCE/state 并交换令牌。插件遵守项目统一授权规则：使用 RS 原生开始接口返回的完整授权 URL，保留其查询参数；取得回调后仅交给 RS 原生完成接口交换和保存 RT。不得为了复制原版的独立服务架构重建 PKCE、删除原生参数或恢复插件 token 交换。

手动、自动、Free 恢复和 Team 切换均共用登录适配器；原账号身份及工作区绑定、原代理、凭据版本、人工暂停、在途保护及设备退出核验继续保留。工作区提取与选择增加严格身份约束；明确失效登录挑战及动态码拒绝采用既有有界恢复，未知失败不重放。TOTP 本地等待保留防止超过截止时间的修正。以上保护不替换登录 HTTP 或 RT 交换实现。

代理、部署网络和上游安全校验仍是独立变量。持续人工安全挑战必须保留真实错误，不承诺所有环境下永远没有 403；真实验收只代表记录中的账号和当次链路。

## 最终状态回读

账号原本处于额度耗尽或限流状态时，成功授权不应把状态强制解释为 `normal`。最终回读接受 RS 的稳定状态并保留现有调度策略；`error` 或未知状态仍进入人工核对。
