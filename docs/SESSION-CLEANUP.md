# 重新授权后登出其他设备

手动与自动重新授权都沿用 `邮箱----密码----2FA` 备注和现有协议登录。所有分支由 RS 原生完成接口交换并首次保存 RT，原生保存后通过身份、工作区、套餐及精确版本检查，再继续执行设备退出与 RT 验证；只有全部步骤通过才将任务记为成功。

1. 插件仅取得 RS 原生流程的授权码回调，保留原 state、PKCE、client_id、redirect_uri 和本次设备 ID，不自行交换令牌。
2. 账号空闲时通过受保护管理 API 暂停调度并回读，再向 RS 原生 OAuth 完成接口提交回调。原生保存后只读核对新 AT、ID Token、RT 存在性及原主体、用户、邮箱、工作区、套餐和精确凭据版本。宿主原生路径尚不提供写回前的完整身份比较，插件暂停隔离与事后核验不能被描述为宿主已完成该修复。
3. 使用本次新 AT、原代理及原设备 ID 读取设备目录。必须恰有一条明确标记 `is_current_device: true` 的会话；缺失、歧义、重复 ID、目录不完整均停止。
4. 逐一撤销其余有有效 `session_id` 的会话。每次撤销前后读回目录，检查本次会话不变、目标消失且没有未知新增会话。不调用全部登出，不移除已登出的受信任设备，不导出设备详情。
5. 调用 RS 原生 `/api/admin/accounts/refresh`，由 RS 刷新并保存轮换结果，再只读核对新 AT、ID Token、工作区、套餐及精确版本，并用刷新后的 AT 再次只读确认同一本次会话、其他会话为空。设备退出进程只获得 AT 与 ID Token，不持有、刷新或保存 RT。
6. 按设备退出前已验证的调度策略恢复：普通授权保留原启停；退回 Free、强制工作区仍停用；自动 Team 切换沿用现有开启调度策略。恢复后读回配置、凭据版本与状态。

设备退出、刷新或写回结果不确定时任务需要人工核对，不自动重放；已暂停的账号保持暂停。取消、超时和插件重启均说明可能的部分退出及暂停状态。重启不自动恢复任务，也不根据旧成功结果再次撤销设备。升级前排队记录缺少新流程标志时按原行为处理，不静默追加退出设备。

若最后恢复调度的响应丢失，启用操作可能已经生效，必须核对实际启停状态，不宣称账号一定仍暂停，也不自动重复开启或再暂停来掩盖不确定性。

任务共享原有 420 秒总时限。协议输出只走私有管道；持久化任务只含流程标志及安全提示，不含 RT、AT、Cookie、设备 ID 或设备目录。

## 接口证据与验证边界

2026-10-20 使用现有 Edge 扩展读取 ChatGPT 公开客户端资源，未登录测试账号、未读取浏览器凭据、未执行任何退出操作：

- [安全设置客户端](https://chatgpt.com/cdn/assets/c2675c8c-nxl2ic2ofk2vw70s.js) 的 `fOt` 使用 `GET /accounts/sessions`，界面读取 `data.devices`。
- 同一资源的 `mOt` 使用 `POST /accounts/sessions/revoke`，正文为 `{"session_id": ...}`；本设备由 `is_current_device` 判断。已退出受信任设备使用另一入口，与本功能无关。
- [请求客户端](https://chatgpt.com/cdn/assets/4813494d-qsuygr73qjc6rh65.js) 的鉴权 API 基址为 `https://chatgpt.com/backend-api`。该资源 SHA-256：`faa2065aa5b0e2804f33ab49788d8e72b240d94b1349f83aa8f7a100110b0732`。

这些是当前第一方客户端使用的内部接口，并非稳定的公开 API 合同。源码与模拟测试不能证明真实账号的授权范围一定允许读取和撤销会话，亦不能证明所有第三方历史 RT 的失效范围。本功能仅在设备目录完整且能核验本次会话时继续。

本地离线测试覆盖唯一设备识别、逐个撤销、空响应、目录回读、RS 原生 RT 刷新、身份变化、部分失败、超时不重放、元数据校验及暂停恢复。真实账号验收需要指定一个允许退出其他设备的账号，并核对其 RS/Chat2API 共享授权、固定出口和在途请求；未完成该验收前不得将模拟结果宣称为生产验证。

## 2026-10-20 原生协议统一

手动、自动、Free 恢复、Team 切换与强制选择全部使用同一原生流程。已有的独立 PKCE 与插件授权码换令牌分支已移除，协议适配器运行时禁止调用本地交换方法。工作区需要修正元数据时，SDK 请求必须逐字段保留原生接口已保存的 AT、RT、ID Token，不以元数据操作代替原生交换和首次保存。未来新增账号的同一约束已写入仓库根目录 [AGENTS.md](../AGENTS.md)。

历史账号可能只有 ID Token、AT 和 RT，没有单独保存 principal。统一实现仅从受保护的已存 ID Token 与 AT 中重建原主体，并同时核对原邮箱、用户与工作区。过期旧令牌只作为原绑定参考，不作为当前有效授权；手动与自动共用这一核验，新原生授权仍须通过完整身份和有效期检查。
